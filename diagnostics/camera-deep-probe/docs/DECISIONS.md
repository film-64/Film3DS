# 技术决策

| 编号 | 选择 | 理由 |
| --- | --- | --- |
| D01 | devkitARM、libctru、Citro2D/Citro3D | 官方 Homebrew 生态可用，云端构建可复现。 |
| D02 | 单外摄 VGA、YUYV 优先，CPU 作为调色基准 | 保留相机交付的分量数据；矩阵、范围和像素顺序可分别测量。RGB565 用于比较。 |
| D03 | Y2R 作为独立诊断路径 | 先实机确认缓存、排列与误差，再判断是否作为预览或转换加速。 |
| D04 | 3D CUBE 和显式输入／输出配置 | 单独审查语法、色彩管理和视觉效果。未知或复合特性显式拒绝。 |
| D05 | 全画面单帧调色、缩放后加颗粒、最后裁切 | 同一源图可重新调色，颗粒大小按最终画布采样，输出保持整数比例。 |
| D06 | F3SR/F3PR、libjpeg-turbo、独立 SD 目录 | 保留源数据与配方，用主机解码交叉验证；原版相册兼容另设测试。 |
| D07 | 原创双屏界面和共享导航模型 | FilmOS 单画布和 Canon 适配需要重构。当前仓库沿用现有 Unlicense，FilmOS 作为独立评估选项。 |
| D08 | F3D1 管道和 SD 批处理 | 云端能端到端执行同一解析器，实机可以先在无网络时收集可复现证据。 |
| D09 | 模拟取景默认启动，外摄通过 L 启用 | 双屏、输入、存储和暗房可在 CAM 出错时分别验证。VGA 实时预览当前使用低频单帧更新。 |
| D10 | ARM11 的 JPEG 使用 libjpeg-turbo 标量构建 | devkitPro 预编译包含 NEON 路径；固定上游版本并审计最终指令。 |
