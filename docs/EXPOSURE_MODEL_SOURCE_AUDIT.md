# 曝光模型原始資料核查

現行 exposure-field/v1 的第三方等效快門預測撤回，不作校準依據。本文件是來源與實作核查，不是已完成校準的聲明。

## 已核實的來源

- Debevec / Malik，作者原始論文與資料： https://www.pauldebevec.com/Research/HDR/ 。方法是從不同已知曝光的影像恢復相機響應函數；影像碼值到曝光量的響應函數是待估參數，不能用一個外部標籤直接替代。
- EMVA 1288 Release 4.0 General，2.1節與圖5： https://www.emva.org/wp-content/uploads/EMVA1288General_4.0Release.pdf 。將黑位扣除後的輸出寫為曝光量的特徵曲線，允許非線性；未知內部處理時，不能套用 Linear 模組的系統增益推導。這是方法參考，不表示目前採集符合EMVA認證程序。
- OpenCV 4.12 官方實作： https://docs.opencv.org/4.12.0/d2/df0/tutorial_py_hdr.html 。CalibrateDebevec/CalibrateRobertson 可從曝光序列估計逆響應；得到相對尺度仍需外部曝光參考錨定。
- GBATEK 原始逆向紀錄： https://mgba-emu.github.io/gbatek/#dsi-aptina-camera-registers-core-3000h-31ffh 。3012h為粗積分、3014h為細積分，302Ah等為各色類比增益代碼、3032h等為核心數字增益。寄存器定義本身不證明經ISP處理的整體曝光響應。這是逆向紀錄，不是已取得的本機原廠資料手冊。

## 與現行錯誤實作對照

1. `field_contract.h:field_fit` 在單標籤時預設 `slope=1`。沒有實測支持，不能輸出已標定的等效快門。
2. `field_capture.h:field_dose` 將積分估計、Gr類比代碼與ISP Gr配置相乘。這沒有驗證跨增益、跨白平衡與ISP狀態的整體響應，不能充當校準完畢的曝光量。
3. sRGB逆轉換只解除所假設的輸出編碼，不能證明已解除感測器ISP本身的曝光/色調曲線。
4. 追到中心區線性亮度0.18，是該控制器的目標達成，不代表第三方ISO100/f2.8曝光值匹配。
5. ±1級粗積分候選不等於已證實的±1級圖像曝光，更不是已證實的正確曝光邊界。應同時輸出實際設定、模型預測、照片，以及相對EV的來源與有效域。

## 現有證據的實際範圍

- 本機已讀到晶片ID `0x2280`。此ID不單憑搜尋到的相似型號手冊就認定為特定原廠型號。
- 既有硬件讀回與幀驗證可證明指定設定是否在採集時保持；它不單獨證明曝光模型正確。
- 舊序列的OpenCV留出驗證：G約+0.0102EV，R約+0.0705EV，B約-0.3551EV；藍通道未通過。結果見 `hardware-auto-01/analysis/opencv-crosscheck`，不能宣稱全通道通過。
- 使用者新報告的1/389秒預測與第三方約1/125秒相差約1.64EV。新輪原件未回收前，不將這個文字讀數虛構成已配對的積分/增益校準點。

## 修正必須證明的內容

先對固定處理狀態建立實測響應與有效域，再用同輪外部曝光標籤定尺度；不同增益/ISP狀態不能依未驗證公式直接合併。用未參與擬合的曝光或新輪次檢查快門/EV誤差，不能回填標籤使本輪預測吻合。保持現有採集證據與UI流程，避免再以另一套自動追亮度流程冒充模型標定。
