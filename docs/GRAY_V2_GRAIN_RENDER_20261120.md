# Film3DS Gray v2 候選曲線與暗房顆粒渲染修正（2026-11-20）

## 實際提交的灰階曲線

- **原始** `romfs/calibration/display-gray.f3isp` 逐位不改：保留當前黑位、白端、白平衡、CCM、相機座標鏡頭陰影補償。原始 `display-color.f3isp` 仍保存在原始碼中，僅**暫時從暗房 UI 停用**，沒有刪除使用者資料。
- **候選** `romfs/calibration/display-gray-v2.f3curve` 為獨立版本 `F3GRAYCURVE1`，5 個數字：EV −0.95，陰影 −0.30、中間調 0、高光 −0.20、肩部 0。候選以 `ROLL0100/0105` 與 `0108–0110` 全幅、Native AE 0 的 YUV/RAW 灰階資料估計，刻意使用簡單、保守的分段 EV 補償，**不是**光譜/色卡/均勻場驗證的正式校準。分段曲線的精度不超過目前的截面配準誤差。這些數字只能當作可回退的試用版，不應當作感光元件物理特性。
- 暗房 `RAW calibration` 循環：`Off`、`Gray original`、`Gray v2 (trial)`。選擇 Gray v2 時先載入完整原始 ISP，再只在**RAW scene 渲染**時疊加候選亮度調整。與使用者的曝光/RAW 自訂調整相加，並遵守原有數值界限；處理不覆寫 DNG、不修改 SD 的 LUT、F3Y、F3E。
- `RAW Curve` 仍是與 ISP 解碼分離的 `Neutral / Shot (approx) / Custom`：Neutral = 零額外曲線；Shot 只是舊的單張 YUV/RAW 分位數估計，對有效 F3Y 配對仍停用自動擬合。Gray v2 是「校準候選」選項，不應讓 Shot 的不精確匹配變成正式參數。

## 畫面方向與顆粒問題

- GPU 顆粒後端的讀回校正原先只用右側上下兩點驗證 **Y** 反向，沒有驗證 **X** 反向。這可能讓照片在 GPU 後端變成左右鏡像；新版在輸出核心外繪製紅、綠、藍三個不同角落標記，判定 X/Y 的 4 種組合，採用成功匹配的方向回填；不符合任何組合會傳回 `FILM_DEVICE`，不會默默輸出可能鏡像的 JPG。
- CPU 與 GPU 都會把暗房 RGB24 圖片寫入上屏預覽紋理。原本一律以 `256×192` 取樣，然後依成品 1:1、3:2、16:9 等長寬比再次縮放，造成**取樣幾何與呈現幾何不一致**。新版依原圖長寬比選擇 256×192 內的實際采樣長方形，UV 與上屏長寬一致。原生 640×480 4:3 相機預覽維持原路徑。
- Host regression：所有 4 種 X/Y GPU 讀回方向、遺失 marker 失敗時的安全處理、非對稱 RGB 像素，與 4:3、1:1、3:2、16:9、3:4 的預覽取樣範圍。正式 GPU 混合仍需實機驗證。
- **仍未證實的部分**：用戶所見「CPU／GPU 都有其他渲染異常」的具體現象，僅憑描述無法判定其像素圖樣、對比度或色彩來源。這次修正了可直接從程式碼確認的共同顯示比例錯誤與 GPU 方向判定漏洞；沒有宣稱每一種殘存的畫質問題都已解決。

## 最小實機驗證

1. 固定同一張包含**不對稱文字**、彩色斜線與 21 階灰階條的 DNG。暗房 RAW calibration 選 `Off`，RAW Curve 選 `Neutral`，顆粒強度 0，先比較 CPU 與 GPU 渲染方向；拍攝畫幅先固定 4:3，再分別試 1:1 與 16:9。
2. 保持同一張 DNG，將顆粒設為 50%，交替使用 CPU 與 GPU；對照左/右的斜線、文字、顆粒密度與邊界接縫。若 GPU 回報 DEVICE，檢查 SD 日誌而非假設成功。
3. 保持 CPU 後端與顆粒 0，RAW calibration 依序選 `Off → Gray original → Gray v2 (trial)`，觀察灰階暗部、中間灰及高光；將每一種成品 JPEG、畫面照片及 `/3ds/Film3DS/log/film3ds.log` 一起帶回。
4. 有實機驗證之前，任何新候選曲線都不應設為全局預設，也不能用 `Shot (approx)` 的元資料替代灰階 21 階實測。

**備註**：編譯／主機測試成功不代表 PICA200 實機 GPU 輸出已通過方向、接縫、混色驗證。此 PR 不觸碰任何原始 SD 資料或 LUT `.cube`。
