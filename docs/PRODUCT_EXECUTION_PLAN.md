# Film3DS 高级拍摄／显影闭环执行计划

更新：2026-11-29。基线：`minmain` 的 `09623ec90869aa5702159098d48425d7e09d6a91`。

## 产品范围

目标是在原生 3DS Camera.app 的拍摄流程中提供可开启的高级功能，以扩展形式集成。
保留原生 JPEG 拍摄，另存关联 DNG，按拍摄时冻结的预设异步冲洗，允许以后继续编辑。
“DLC”在这里描述产品集成形态，不预先假定官方 DLC 加载机制或已验证的注入方式。
原生取景与 RAW 显影解耦；实时胶片取景和取景／成片逐像素一致不属于当前闭环前置条件。

没有实机不阻塞显影、配方、任务状态和宿主端集成验证。传感器校准、采集时序、
Camera.app 挂接、GPU 行为及设备速度必须另列实机验收，不能由宿主测试替代。
当前独立应用用于开发验证，不把它误记为 Camera.app 已接入。

| 3 后台冲洗 | 原片／配方提交后持久入队；冻结预设；单任务资源预算；明确失败、取消、恢复及输出发布 | 重启／中断／磁盘满／损坏原片／缺失 LUT 测试；任务可恢复且不重复发布；原件保持 | 2 |
| 4 宿主闭环 | 拍摄输入接口、照片标识、原生 JPEG 与 DNG 关联、输出与编辑入口 | 用固定 JPEG+DNG 模拟采集，跑通保存→入队→冲洗→重启→编辑→再次冲洗 | 3 |
| 5 原生集成 | 高级模式入口、Camera.app 资源归属、采集接入和相册结果呈现 | 实机验证 JPEG 不受影响、两份原件的时序／关联、连续拍摄和资源恢复 | 4；接入研究可提前进行 |
| 6 发布 | 收敛 UI、文档与安装包；硬件矩阵、校准资产与性能验收 | 同一版本可安装、可恢复编辑、可追溯；明确支持镜头、机型与限制 | 5 |

阶段 1D 不要求一次支持所有厂商。每个适配器须声明准确版本、色域、编码、范围及参考源。
不得以新增一条任意曲线替代标准 Log 编码，也不得把 Log 编码当作额外传感器动态范围。

## 处理模型

不可变 DNG → 传感器解码／校准 → 浮点工作场景 → WB／线性曝光／前置调整
→ 目标色域及输入编码 → LUT → 输出空间解释／必要显示映射 → 后置调整
→ 几何／细节／颗粒 → JPEG。

“三层”指前置创作调整、技术输入编码、后置创作调整。白平衡是线性阶段操作。
LUT 已完成显示映射时不额外叠加默认显示映射；输出仍为 Log／场景数据时明确补齐。
现有 RAW shoulder 和 legacy tone 路径必须先做兼容测试，通过版本化配方引入新行为，
不悄悄重解释旧配方。固定工作空间及标定的真实性是独立问题：本轮转换按
linear BT.709/D65 为基准，不宣称当前未校准 RAW 已具有准确 BT.709 颜色。

## 测试分层

- 数学参考：标准灰点、色域基向量、编码分段点、负值、超白和往返误差。
- 图像参考：合成渐变／色块及现有 DNG，检验曝光、WB、曲线、LUT 和不变原件。
- 持久化／队列：崩溃边界、文件关联、配方版本、资源缺失、原子发布和恢复。
- 实机：原生拍摄挂接、同次拍摄时序、DMA、GPU、SD、内存、响应时间和颜色校准。

## 本批交付边界

阶段 0／1A 已实现：执行计划、编码模块、已有 F-Log2 C 输出支持及回归测试。
本轮增加阶段 1B 的外置旁车：精确文件绑定、输入／输出编码、明确的前置 RAW shoulder 策略，
并验证阶段 1C 的 WB／曝光／LUT／后置曲线顺序。细节及边界见 LUT_ADAPTER.md。
阶段 1C 新增线性 RAW 中性选区拟合核心与只读主机命令，结果复用既有配方 WB 字段，
有覆盖率／色度离散／拟合误差检查；见 NEUTRAL_WHITE_BALANCE.md。设备触屏取样入口尚未接入。
阶段 1B 的完整处理意图／强摘要资产归档，以及阶段 1C 的统一输出映射仍待完成。
完整配方、后台队列、Camera.app 集成都不能据此标记完成。
现有原生取景、RAW 采集、DNG 存储、旧配方与未配置旁车的 LUT 保留原行为。
未来任务调度必须更新现有 runtime contract，并为资源归属与失败行为增加测试。

所有开发分支以 `minmain` 为基线，PR 目标为 `minmain`，不自动合并或发布到 `主要`。
